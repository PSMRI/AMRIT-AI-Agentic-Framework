# Information Checklist

Use this checklist to identify critical gaps. Ask only focused questions not already answered by the user, attachments, Confluence, or Jira. If the user requests a draft despite gaps, label them visibly.

## Feature decomposition

- Approved source title, version, location, and explicit approval status
- Business objective and approved scope
- Source requirement IDs and sections
- Actors, roles, modules, workflows, and expected outcomes
- Business rules, validations, permissions, states, notifications, reports, and integrations
- Dependencies, exclusions, limitations, risks, and unresolved decisions
- Existing related Epics, Stories, terminology, and labels

Do not decompose an unapproved source as finalized scope. Offer a clearly provisional draft only with explicit user direction.

## Defect intake

- Existing issue key or L2 escalation reference
- Affected application, module, environment, users, services, or sites
- Expected and observed behavior
- Reproduction steps, frequency, timestamps, and evidence
- Business and operational impact, urgency, and workaround
- Existing severity, priority, status, labels, and linked incidents
- Related documentation, previous defects, and possible duplicates
- Confirmation that the issue affects production

Record `Root cause not established; analysis required.` unless evidence already establishes it. Preserve **CAPA required at closure** for production defects.

## Prioritization

- Affected population and breadth
- Impact and urgency
- Production status
- Regulatory or programme relevance
- Dependency or release pressure
- Workaround availability and cost
- Evidence for each factor
- Target project's actual priority options

## Jira publication

- Approved backlog version and approving human
- Separate explicit Jira publication request
- Target Jira project
- Create versus update decisions
- Current issue types and supported hierarchy
- Required fields and valid field options
- Module, category, priority, labels, and components
- Parent-child relationships
- Duplicate-check outcome
- Unresolved fields
- CAPA-required classification or tagging, when applicable
- Final pre-publish preview

Do not publish while any required item is unresolved.
